
- PHP 7.4 builds bundle PCRE2 10.35, which compiles an unknown Unicode property such as `\p{Foo}` (it matches nothing);
  PCRE2 10.44 refuses it, and 10.43+ also accepts variable-length lookbehind. A test that needs a pattern PCRE cannot
  compile on every PHP line uses an unbalanced group (`a(`).

- **`Valid` не вкладывается ни в какой Composite (2026-10-14 UTC).** Symfony `Composite::initializeNestedConstraints` бросает `ConstraintDefinitionException` для `Valid` внутри любого составного ограничения (`Property`, `IfThenElse`, `All`…), причём только при загрузке метаданных — генерация и `php -l` это не ловят. `ConstraintBuilder::build()` (через `nested()`) единственный даёт `Valid`; `narrowings()` его отбрасывает — объект обходит `Valid` свойства родителя. Нашлось на OpenAI: общие свойства вариантов поднимаются в union-базу, а декларация варианта становится «сужением». Корпусный `load.php` читает метаданные Validator — гонять его после изменений в составных ограничениях.
- **Интерфейсная union-база (core 1.6, `ClassKind::INTERFACE`)** мосту не требует особой обработки: `DiscriminatorMap` на интерфейсе Symfony читает при (де)нормализации на 5.4–8 (`RealSymfonyTest::testBuildsTheVariantAnInterfaceSelects`); у интерфейса нет свойств, поэтому энричеры свойств его не трогают. Порядок путей нарушений между 5.4/6.4 и 7+ различается — сортировать в тестах.
- **Интерфейс не несёт ограничений (2026-10-14 UTC).** `ValidatorEnricher::enrichClass` для `ClassKind::INTERFACE` только предупреждает о объектных keywords схемы (`required`, `additionalProperties` — структурные в core, проверяются через `required()`/`additionalProperties()`, остальные через `hasKeyword`) и помечает их `keywordChecks()->checked()`, чтобы core не дублировал «"not" is not supported». Ограничения на интерфейсе не пишем: Symfony сливает их в реализации под группой интерфейса — поведение групп не проверено на 5.4–8.
- **Члены union без дискриминатора (2026-10-14 UTC, `MemberConstraints`).** Проверяются, только если генератор типизирует значение как скаляры PHP (`isScalar` по `TypeModel`: даты, `x-php-type`, PHP enum — любой `enum`, даже из одного значения, и `{const: null}`, который даёт `mixed`, — отсекаются), union стоит в одном месте (не считая «член + null», как у nullable `$ref`), без `oneOf`+`anyOf` и без `integer`+`number` (5.0 — integer в JSON Schema, не в PHP). Каждый член — скаляр одного «говорящего» места (аннотации `Subschema::annotates` — единый список и для `RawSchema` — не считаются; `allOf` даёт второе место и отсекается в `place()`), без вложенных union, `properties` и «своих» keywords моста. Член без `type` с `const` берёт тип значения `const`. Член собирается через `subschema()` с `MixedType` (даёт `Type` первым); несколько ограничений — `Sequentially` **с группами значения** (Symfony фиксирует группы вложенного composite при создании; `AtLeastOneOf`/`ExactlyOneOf`/`Sequentially` в `ConstraintSpec::isComposite`, чтобы `All` их тоже передавал). На PHP 7.4 свойство нетипизировано — `Type` пишется всегда. Иначе — старый путь (предупреждение только для «своих» keywords; `minLength` и т.п. теряются молча, как и раньше). `ExactlyOneOf` гейтится runtime 1.3.
- **Объектный default (core 1.9, 2026-10-21 UTC).** `default: {}` у свойства-класса ядро с PHP 8.1 даёт `new Owner()` в параметре конструктора; мосту ничего не нужно: Serializer берёт `ReflectionParameter::getDefaultValue()` для отсутствующего ключа, `Valid` проверяет созданный объект, а правила «default ⇒ всегда задано» (`DependentRequirements::unlessAlwaysSet`, `ClassConditions::namesAlwaysSet`) верны и для объекта. `RealSymfonyTest::testTakesAnObjectDefaultWhereTheTargetCanCreateIt` (схема `Den`) проверяет это возможностью, а не версией (локально ядро — symlink с меткой 1.6.0); на 8.2 при наличии `ObjectDefaults` в ядре объект обязателен. Классы immutable, поэтому невалидный owner берётся из payload — `Valid` у свойства один и тот же.
- **`sources[].operations` (core 1.10, 2026-10-21 UTC, проверено чтением кода).** Ключ живёт в файле конфига генератора, мост его не разбирает; `BuildDtosPass` меняет только корень вывода (`withOutputRoot`), `SourceConfig::withOutputDir` фильтр операций сохраняет.

- **defaultMapping / defaultType** (2026-10-22 UTC): `SerializerEnricher::defaultType` пишет `defaultType` в `DiscriminatorMap` (Symfony ≥ 7.3, `DEFAULT_TYPE_SINCE`) значением `DiscriminatorModel::defaultValue()` (первый ключ маппинга на класс по умолчанию; null → warning). Мост требует ядро ^1.11 (с 1.6.0 моста): совместимость с ядром без `defaultClass()` через `method_exists` не прошла CI — jobs PHPStan/Infection берут `vendor` из кэша по хешу `composer.json` со старым ядром (поднятие требования заодно сбрасывает кэш). Symfony берёт `defaultType` только при отсутствии ключа; неизвестное значение → исключение (5.4: `RuntimeException`, позже `NotNormalizableValueException`; в тесте — `ExceptionInterface`). Нормализация класса по умолчанию пишет его собственное значение из карты поверх хранимого (`memo` → `Note`).

- **oneOf/anyOf рядом со свойствами класса** (2026-10-22 UTC): `ClassConditions::alternated()` (статический, общий для гейта в `ValidatorEnricher::conditions` и `alternatives()`) — места Keywords с членами и без дискриминатора. Член — ветка `[properties, required]` (`member()`): inline-объект без `$ref`/enum/allOf/union/discriminator/items/схемы additionalProperties, сырые ключевые слова только аннотации, свойства — `RawSchema::flat`. oneOf → runtime `ExactlyOneOf` (1.3), ветки из >1 проверки — в `Sequentially`. anyOf → runtime `Not` из `Not` на ветку (1.2; `MINIMUM_OF['anyOf']`), потому что Symfony `AtLeastOneOf` НЕ может стоять на классе (поймал интеграционный тест: «cannot target class»). Ветка без проверок: в oneOf → warning на члене, не проверяем; в anyOf → anyOf всегда истинен, без warning. Член с `additionalProperties: false` (а не только схемой) отклоняется (`isPlain`) — ревью CR-001. anyOf-Not с message «should satisfy at least one». Отклонено: вынос `ClassAlternatives` из 500-строчного `ClassConditions` (SRP, отдельный рефакторинг); предупреждение о nullable в oneOf — описано в README как ограничение. Пустой payload при `oneOf` с `properties` в вариантах валиден, если ровно одна ветка проходит (properties проверяют только присутствующие ключи). Родительский union до наследника не доходит (проверено мутантом), поэтому `ofAncestor` не нужен.
- **Сравнение значений в Keywords** (2026-10-22 UTC): одно определение равенства — `key()`: целый float в диапазоне int → int (в т.ч. -0.0 → 0), прочие float — по битам `pack('E')` (не зависит от `serialize_precision`), остальное — `serialize` после `exact()` (в массивах -0.0 → 0.0; Rector сворачивает `$x === 0.0 ? 0.0 : $x` как тавтологию — поэтому `abs($x)`). `values()` и `enum()`/`common()` идут по ключу, `same()`/`contains()` удалены (старое `same()` не было транзитивным для int > 2^53 и float). Float внутри массивов сериализуются с `serialize_precision` (по умолчанию -1 — точно). Отклонено ревью CR-006 (`$listed[$key] = true` — давало эквивалентного мутанта).
- **Целость float в `Keywords::exact` и Standard compliance** (2026-10-23 UTC): `fmod($value, 1.0) === 0.0`, не `floor($value) === $value`: у `floor` RoundingFamily даёт эквивалентного мутанта `ceil`, а игнор в `infection.json5` валит задачу «Standard compliance» в CI (файл должен совпадать с шаблоном; v1.7.0 вышел с этой ошибкой, исправлено 2026-10-23 UTC). Округление `(float) (int) $v === $v` тоже не годится: проверка диапазона становится эквивалентной, а PHP 8.5 предупреждает о приведении float вне диапазона. Локально стандарт проверяется `php bundle-standard/bin/verify-standard.php .` (тег из `checks.yml`).
- **Синхронизация с генератором 1.14** (2026-10-23 UTC): `Keywords` повторяет два новых правила генератора (его `SchemaShape` внутренний): `isPlainObject` — член allOf `{type: object}` выкидывается из typed-членов в `unwrap`, если остался другой (иначе `resolved()` = внешняя схема и терялись `All`/`Valid`/`x-php-type`); `contradictsItsEnum` — `enums()` пропускает enum, ни одно строковое/целое значение которого `type` не допускает (иначе `Choice` на массиве/строке — ни одно значение не проходит). Требование ядра не поднято: allOf-случай со старым генератором — ошибка генерации, а противоречащий enum старый генератор генерировал (с warning) — `Choice` убирается при любой версии, это только лучше. Не проверено (CR-007): голый подтип 1.14 (`allOf: [$ref Base-с-discriminator, {type: object}]` → пустой подкласс) — интеграционного теста моста нет. Мутанты тестов моста часто уходят в таймаут (реальный генератор), MSI это засчитывает.

- **Хвосты 2026-10-25 UTC.** (a) m-2: `narrowings()` различает причину, по которой Valid потомка не попал в `$checked`: если родительская декларация сама дала бы Valid (`traverses()`), значит её убрали группы/skip → прежнее «The parent skips…»; иначе тип родителя — не класс (вариант держит родительский `{type: object}` = массив) → «"x" keeps the type … of the parent, which holds no object to traverse…». (b) Интеграционные тесты `RealSymfonyTest`: `Setting.value` → рекурсивный `JsonValue` (union со списком и map самого себя; туда-обратно без изменений) и bare subtype `Square` (`allOf: [$ref Shape, {type: object}]`, дискриминатор без mapping) — проходят на 8.0/8.2 (7.4 скип, как у соседей). (c) `admitsNull` для `allOf` без `type` (Shipengine `origin_address: allOf [$ref Address]` не получал `Present`) — решается переходом на `ClassModel::requiredInherited()` ядра 1.16 (там nullability считает TypeMapper ядра); ждёт релиза ядра.
- `setsItsOwnChecks(Schema)` — единый предикат «x-validator-groups или x-validator-skip === true» (ревью CR-002/003: `has('x-validator-skip')` считал `false` пропуском, остальной энричер читает флаг через `ExtensionReader::flag`).
