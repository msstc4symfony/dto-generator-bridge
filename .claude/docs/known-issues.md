
- PHP 7.4 builds bundle PCRE2 10.35, which compiles an unknown Unicode property such as `\p{Foo}` (it matches nothing);
  PCRE2 10.44 refuses it, and 10.43+ also accepts variable-length lookbehind. A test that needs a pattern PCRE cannot
  compile on every PHP line uses an unbalanced group (`a(`).

- **`Valid` не вкладывается ни в какой Composite (2026-10-14 UTC).** Symfony `Composite::initializeNestedConstraints` бросает `ConstraintDefinitionException` для `Valid` внутри любого составного ограничения (`Property`, `IfThenElse`, `All`…), причём только при загрузке метаданных — генерация и `php -l` это не ловят. `ConstraintBuilder::build()` (через `nested()`) единственный даёт `Valid`; `narrowings()` его отбрасывает — объект обходит `Valid` свойства родителя. Нашлось на OpenAI: общие свойства вариантов поднимаются в union-базу, а декларация варианта становится «сужением». Корпусный `load.php` читает метаданные Validator — гонять его после изменений в составных ограничениях.
- **Интерфейсная union-база (core 1.6, `ClassKind::INTERFACE`)** мосту не требует особой обработки: `DiscriminatorMap` на интерфейсе Symfony читает при (де)нормализации на 5.4–8 (`RealSymfonyTest::testBuildsTheVariantAnInterfaceSelects`); у интерфейса нет свойств, поэтому энричеры свойств его не трогают. Порядок путей нарушений между 5.4/6.4 и 7+ различается — сортировать в тестах.
- **Интерфейс не несёт ограничений (2026-10-14 UTC).** `ValidatorEnricher::enrichClass` для `ClassKind::INTERFACE` только предупреждает о объектных keywords схемы (`required`, `additionalProperties` — структурные в core, проверяются через `required()`/`additionalProperties()`, остальные через `hasKeyword`) и помечает их `keywordChecks()->checked()`, чтобы core не дублировал «"not" is not supported». Ограничения на интерфейсе не пишем: Symfony сливает их в реализации под группой интерфейса — поведение групп не проверено на 5.4–8.
- **Члены union без дискриминатора (2026-10-14 UTC, `MemberConstraints`).** Проверяются, только если генератор типизирует значение как скаляры PHP (`isScalar` по `TypeModel`: даты, `x-php-type`, PHP enum — любой `enum`, даже из одного значения, и `{const: null}`, который даёт `mixed`, — отсекаются), union стоит в одном месте (не считая «член + null», как у nullable `$ref`), без `oneOf`+`anyOf` и без `integer`+`number` (5.0 — integer в JSON Schema, не в PHP). Каждый член — скаляр одного «говорящего» места (аннотации `Subschema::annotates` — единый список и для `RawSchema` — не считаются; `allOf` даёт второе место и отсекается в `place()`), без вложенных union, `properties` и «своих» keywords моста. Член без `type` с `const` берёт тип значения `const`. Член собирается через `subschema()` с `MixedType` (даёт `Type` первым); несколько ограничений — `Sequentially` **с группами значения** (Symfony фиксирует группы вложенного composite при создании; `AtLeastOneOf`/`ExactlyOneOf`/`Sequentially` в `ConstraintSpec::isComposite`, чтобы `All` их тоже передавал). На PHP 7.4 свойство нетипизировано — `Type` пишется всегда. Иначе — старый путь (предупреждение только для «своих» keywords; `minLength` и т.п. теряются молча, как и раньше). `ExactlyOneOf` гейтится runtime 1.3.
