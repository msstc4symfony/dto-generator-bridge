
- PHP 7.4 builds bundle PCRE2 10.35, which compiles an unknown Unicode property such as `\p{Foo}` (it matches nothing);
  PCRE2 10.44 refuses it, and 10.43+ also accepts variable-length lookbehind. A test that needs a pattern PCRE cannot
  compile on every PHP line uses an unbalanced group (`a(`).

- **`Valid` не вкладывается ни в какой Composite (2026-10-14 UTC).** Symfony `Composite::initializeNestedConstraints` бросает `ConstraintDefinitionException` для `Valid` внутри любого составного ограничения (`Property`, `IfThenElse`, `All`…), причём только при загрузке метаданных — генерация и `php -l` это не ловят. `ConstraintBuilder::build()` (через `nested()`) единственный даёт `Valid`; `narrowings()` его отбрасывает — объект обходит `Valid` свойства родителя. Нашлось на OpenAI: общие свойства вариантов поднимаются в union-базу, а декларация варианта становится «сужением». Корпусный `load.php` читает метаданные Validator — гонять его после изменений в составных ограничениях.
- **Интерфейсная union-база (core 1.6, `ClassKind::INTERFACE`)** мосту не требует особой обработки: `DiscriminatorMap` на интерфейсе Symfony читает при (де)нормализации на 5.4–8 (`RealSymfonyTest::testBuildsTheVariantAnInterfaceSelects`); у интерфейса нет свойств, поэтому энричеры свойств его не трогают. Порядок путей нарушений между 5.4/6.4 и 7+ различается — сортировать в тестах.
- **Интерфейс не несёт ограничений (2026-10-14 UTC).** `ValidatorEnricher::enrichClass` для `ClassKind::INTERFACE` только предупреждает о объектных keywords схемы (`required`, `additionalProperties` — структурные в core, проверяются через `required()`/`additionalProperties()`, остальные через `hasKeyword`) и помечает их `keywordChecks()->checked()`, чтобы core не дублировал «"not" is not supported». Ограничения на интерфейсе не пишем: Symfony сливает их в реализации под группой интерфейса — поведение групп не проверено на 5.4–8.
- **Члены union без дискриминатора (2026-10-14 UTC, `MemberConstraints`).** Проверяются, только если генератор типизирует значение как скаляры PHP (`isScalar` по `TypeModel`: даты, `x-php-type`, PHP enum — любой `enum`, даже из одного значения, и `{const: null}`, который даёт `mixed`, — отсекаются), union стоит в одном месте (не считая «член + null», как у nullable `$ref`), без `oneOf`+`anyOf` и без `integer`+`number` (5.0 — integer в JSON Schema, не в PHP). Каждый член — скаляр одного «говорящего» места (аннотации `Subschema::annotates` — единый список и для `RawSchema` — не считаются; `allOf` даёт второе место и отсекается в `place()`), без вложенных union, `properties` и «своих» keywords моста. Член без `type` с `const` берёт тип значения `const`. Член собирается через `subschema()` с `MixedType` (даёт `Type` первым); несколько ограничений — `Sequentially` **с группами значения** (Symfony фиксирует группы вложенного composite при создании; `AtLeastOneOf`/`ExactlyOneOf`/`Sequentially` в `ConstraintSpec::isComposite`, чтобы `All` их тоже передавал). На PHP 7.4 свойство нетипизировано — `Type` пишется всегда. Иначе — старый путь (предупреждение только для «своих» keywords; `minLength` и т.п. теряются молча, как и раньше). `ExactlyOneOf` гейтится runtime 1.3.
- **Объектный default (core 1.9, 2026-10-21 UTC).** `default: {}` у свойства-класса ядро с PHP 8.1 даёт `new Owner()` в параметре конструктора; мосту ничего не нужно: Serializer берёт `ReflectionParameter::getDefaultValue()` для отсутствующего ключа, `Valid` проверяет созданный объект, а правила «default ⇒ всегда задано» (`DependentRequirements::unlessAlwaysSet`, `ClassConditions::namesAlwaysSet`) верны и для объекта. `RealSymfonyTest::testTakesAnObjectDefaultWhereTheTargetCanCreateIt` (схема `Den`) проверяет это возможностью, а не версией (локально ядро — symlink с меткой 1.6.0); на 8.2 при наличии `ObjectDefaults` в ядре объект обязателен. Классы immutable, поэтому невалидный owner берётся из payload — `Valid` у свойства один и тот же.
- **`sources[].operations` (core 1.10, 2026-10-21 UTC, проверено чтением кода).** Ключ живёт в файле конфига генератора, мост его не разбирает; `BuildDtosPass` меняет только корень вывода (`withOutputRoot`), `SourceConfig::withOutputDir` фильтр операций сохраняет.

- **defaultMapping / defaultType** (2026-10-22 UTC): `SerializerEnricher::defaultType` пишет `defaultType` в `DiscriminatorMap` (Symfony ≥ 7.3, `DEFAULT_TYPE_SINCE`) значением `DiscriminatorModel::defaultValue()` (первый ключ маппинга на класс по умолчанию; null → warning). Мост требует ядро ^1.11 (с 1.6.0 моста): совместимость с ядром без `defaultClass()` через `method_exists` не прошла CI — jobs PHPStan/Infection берут `vendor` из кэша по хешу `composer.json` со старым ядром (поднятие требования заодно сбрасывает кэш). Symfony берёт `defaultType` только при отсутствии ключа; неизвестное значение → исключение (5.4: `RuntimeException`, позже `NotNormalizableValueException`; в тесте — `ExceptionInterface`). Нормализация класса по умолчанию пишет его собственное значение из карты поверх хранимого (`memo` → `Note`).

- **oneOf/anyOf рядом со свойствами класса** (2026-10-22 UTC): `ClassConditions::alternated()` (статический, общий для гейта в `ValidatorEnricher::conditions` и `alternatives()`) — места Keywords с членами и без дискриминатора. Член — ветка `[properties, required]` (`member()`): inline-объект без `$ref`/enum/allOf/union/discriminator/items/схемы additionalProperties, сырые ключевые слова только аннотации, свойства — `RawSchema::flat`. oneOf → runtime `ExactlyOneOf` (1.3), ветки из >1 проверки — в `Sequentially`. anyOf → runtime `Not` из `Not` на ветку (1.2; `MINIMUM_OF['anyOf']`), потому что Symfony `AtLeastOneOf` НЕ может стоять на классе (поймал интеграционный тест: «cannot target class»). Ветка без проверок: в oneOf → warning на члене, не проверяем; в anyOf → anyOf всегда истинен, без warning. Член с `additionalProperties: false` (а не только схемой) отклоняется (`isPlain`) — ревью CR-001. anyOf-Not с message «should satisfy at least one». Отклонено: вынос `ClassAlternatives` из 500-строчного `ClassConditions` (SRP, отдельный рефакторинг); предупреждение о nullable в oneOf — описано в README как ограничение. Пустой payload при `oneOf` с `properties` в вариантах валиден, если ровно одна ветка проходит (properties проверяют только присутствующие ключи). Родительский union до наследника не доходит (проверено мутантом), поэтому `ofAncestor` не нужен.
- **Сравнение значений в Keywords** (2026-10-22 UTC): одно определение равенства — `key()`: целый float в диапазоне int → int (в т.ч. -0.0 → 0), прочие float — по битам `pack('E')` (не зависит от `serialize_precision`), остальное — `serialize` после `exact()` (в массивах -0.0 → 0.0; Rector сворачивает `$x === 0.0 ? 0.0 : $x` как тавтологию — поэтому `abs($x)`). `values()` и `enum()`/`common()` идут по ключу, `same()`/`contains()` удалены (старое `same()` не было транзитивным для int > 2^53 и float). Float внутри массивов сериализуются с `serialize_precision` (по умолчанию -1 — точно). Отклонено ревью CR-006 (`$listed[$key] = true` — давало эквивалентного мутанта).
- **Целость float в `Keywords::exact` и Standard compliance** (2026-10-23 UTC): `fmod($value, 1.0) === 0.0`, не `floor($value) === $value`: у `floor` RoundingFamily даёт эквивалентного мутанта `ceil`, а игнор в `infection.json5` валит задачу «Standard compliance» в CI (файл должен совпадать с шаблоном; v1.7.0 вышел с этой ошибкой, исправлено 2026-10-23 UTC). Округление `(float) (int) $v === $v` тоже не годится: проверка диапазона становится эквивалентной, а PHP 8.5 предупреждает о приведении float вне диапазона. Локально стандарт проверяется `php bundle-standard/bin/verify-standard.php .` (тег из `checks.yml`).
- **Синхронизация с генератором 1.14** (2026-10-23 UTC): `Keywords` повторяет два новых правила генератора (его `SchemaShape` внутренний): `isPlainObject` — член allOf `{type: object}` выкидывается из typed-членов в `unwrap`, если остался другой (иначе `resolved()` = внешняя схема и терялись `All`/`Valid`/`x-php-type`); `contradictsItsEnum` — `enums()` пропускает enum, ни одно строковое/целое значение которого `type` не допускает (иначе `Choice` на массиве/строке — ни одно значение не проходит). Требование ядра не поднято: allOf-случай со старым генератором — ошибка генерации, а противоречащий enum старый генератор генерировал (с warning) — `Choice` убирается при любой версии, это только лучше. Не проверено (CR-007): голый подтип 1.14 (`allOf: [$ref Base-с-discriminator, {type: object}]` → пустой подкласс) — интеграционного теста моста нет. Мутанты тестов моста часто уходят в таймаут (реальный генератор), MSI это засчитывает.

- **Хвосты 2026-10-25 UTC.** (a) m-2: `narrowings()` различает причину, по которой Valid потомка не попал в `$checked`: если родительская декларация сама дала бы Valid (`traverses()`), значит её убрали группы/skip → прежнее «The parent skips…»; иначе тип родителя — не класс (вариант держит родительский `{type: object}` = массив) → «"x" keeps the type … of the parent, which holds no object to traverse…». (b) Интеграционные тесты `RealSymfonyTest`: `Setting.value` → рекурсивный `JsonValue` (union со списком и map самого себя; туда-обратно без изменений) и bare subtype `Square` (`allOf: [$ref Shape, {type: object}]`, дискриминатор без mapping) — проходят на 8.0/8.2 (7.4 скип, как у соседей). (c) `admitsNull` для `allOf` без `type` (Shipengine `origin_address: allOf [$ref Address]` не получал `Present`) — решено 2026-10-27 UTC: `narrowings()` берёт `class->requiredInherited()` минус `ancestors[0]->requiredInherited()` (родительский `Present` наследуется Symfony; список ядра кумулятивный от корня). `mixed` теперь требуется (`Present`), как и в конструкторе ядра; общий дискриминатор, обязательный во всех вариантах, ядро делает обязательным в базе → `Present` у варианта больше нет.
- `setsItsOwnChecks(Schema)` — единый предикат «x-validator-groups или x-validator-skip === true» (ревью CR-002/003: `has('x-validator-skip')` считал `false` пропуском, остальной энричер читает флаг через `ExtensionReader::flag`).
- Повторное ревью: `x-validator-groups: null` — не свои группы (как `ExtensionReader::groups()`); предупреждение вынесено в `warnAboutAnUncheckedObject()`; `traverses`/`setsItsOwnChecks` — static; тест на `otherDeclarations` со `skip: false` и `groups: null`.
- **Форматы по имени (feat/formats, 2026-10-26 UTC).** `Keywords::formats()` отдаёт `Schema::normalizedFormat()` (ядро 1.16+, constraint `^1.16` в composer.json/composer-ci.json; локальный `composer-local.json` не в git). Проверки форматов строк — `Validator\FormatConstraints` (таблицы CONSTRAINTS / PATTERNS / INTL), `KindConstraints` оставил себе диапазоны целых (`INTEGER_BOUNDS`: int8/16/32, uint8/16/32, uint64 — только нижняя граница; метка `format: X`). Сознательно НЕ используются: `Url` (не берёт `urn:`; `url` в ядре = `uri-reference`, без проверки), `Currency` (Stripe пишет `usd`) → Regex 3 букв, `MacAddress` (только 7.1+) → Regex, libphonenumber/odolbeau `PhoneNumber` (Twilio `friendly_name` `(800) 555-1234`, Linode `555-555-5555` национальные — без региона были бы отвергнуты) → мягкий Regex `FormatPatterns::PHONE`. `Country`/`Language`/`Locale` — только при `symfony/intl` в InstalledPackages (иначе warning). Значение нескольких типов теперь предупреждает обо всех проверяемых форматах (раньше только int32/byte/uri/time). RFC 2822 (`date-time-rfc-2822`) — `Serializer\Context(context: [datetime_format => 'D, d M Y H:i:s O'])`. Тест-хелпер `attributesOf` не переваривает многострочные `Regex(` — для паттернов `assertMatchesRegularExpression` по тексту кода; принтер пишет паттерн в одинарных кавычках без удвоения `\`.
- **Ревью форматов (2026-10-26 UTC).** `Bic` бросает LogicException уже в конструкторе без `symfony/intl` (падает загрузка метаданных всего класса) → под intl-гейтом вместе с Country/Language/Locale. `Timezone(zone: \DateTimeZone::ALL_WITH_BC)` — иначе `Asia/Calcutta`, `US/Pacific`, `GMT` отвергаются. `http-method` — RFC 9110 token в любом регистре (Twilio enum `get`/`GET`). `hex-color` в ядре — отдельный формат (не алиас `color`), Regex с/без `#`; `color`/`css-color` → CssColor. PHONE с флагом `u` (NBSP, en dash): невалидный UTF-8 → preg_match false → Symfony Regex = нарушение. Известные ограничения в README: Uuid не берёт nil/`{…}`, Bic/Country в нижнем регистре, duration без знака и дробей кроме секунд, RFC 2822 без дня недели. Diff-инфекция в мосте: `vendor/bin/infection` (не tools/). Принтер пишет `'` в паттерне как `\'` — тестовый regex-хелпер это повторяет.
- **Второе ревью форматов (2026-10-26 UTC).** CR-N1: в подсхемах (`not`/`if`/`oneOf`/…, `ConstraintBuilder::subschema` строит с `$subschema = true`) формат, который мост не проверяет (`uri-reference`, `password`, неизвестный), пишет `"format: X" is not checked.` в собственный `Diagnostics` подсхемы → существующий механизм «"not" is not checked, as part of its schema cannot be» отбрасывает ключевое слово (иначе `Not([])` отвергал бы любую строку, `if: []` всегда давал `then`). На верхнем уровне формат — аннотация, молчим. Constant-аргументы — таблица `FormatConstraints::CONSTANT_OPTIONS`. Отклонено: CR-N9 (причина для intl-формата на значении нескольких типов — текст «checks only a string» верен независимо от intl); CR-N11 (`RuntimeConstraints` создают вызывающие и делят его экземпляр/предупреждения между билдерами класса — переносить внутрь нельзя).
- **Третье ревью форматов (2026-10-26 UTC).** CR-T1: строгое правило подсхем только для `not`/`if`/`oneOf` (`ConstraintBuilder::subschema` решает по `$keyword`); в монотонных позициях (`anyOf`, `then`/`else`, `patternProperties`, `prefixItems`, `unevaluatedItems`, `propertyNames`, `contains`) непроверяемый формат снова молча игнорируется — иначе терялись проверки, которые были в main. `contains` с `maxContains` не строгий (редко; ошибка в сторону лишнего пропуска). CR-T2: в строгой подсхеме на числе/булеве формат, не являющийся строковым и не дающий диапазон int (`unix-time`, `int64`, неизвестный), тоже делает подсхему непроверяемой; строковый формат (`email`) на числе по JSON Schema совпадает с любым — `not` честно отвергает всё.
- **Отключение форматов (feat/format-switches, 2026-10-26 UTC).** `extensionConfig.symfony.formats`: `true` (по умолчанию) | `false` | список «только эти» | карта `формат → bool` поверх «всё включено». Разбор — `Settings::parseFormats()` (имена через `Formats::normalize`; неизвестный мосту формат, повтор после нормализации, пустой массив (`[]`/`{}` в YAML неразличимы и значили бы противоположное) — ошибки конфига; дата — ошибка с пояснением про `DateTimeInterface`). Значение — `Validator\FormatChecks::allows()`; что мост вообще умеет — `FormatConstraints::known()` (= `checks() || KindConstraints::rangesIntegersOf()`), передаётся в `ConstraintBuilder` → `FormatConstraints` и `KindConstraints`. Отключённый формат = непроверяемый: без constraint, без предупреждения «value may be of another type», в подсхемах `not`/`if`/`oneOf` — `"format: X" is not checked.` (иначе `not: {format: phone}` отвергал бы любую строку). На ошибочных ветках разбор возвращает null, а `fromConfig` бросает при `$problems !== [] || null` — фабрика `all()` давала эквивалентный мутант.
  Ревью (2026-10-26 UTC): имя везде `$formatChecks`; ошибки формы собираются вместе с остальными (флаг `$shaped`). Отклонено CR-008 (9 параметров конструктора `ConstraintBuilder`, context-объект) — длинный список был и раньше, рефакторинг всех вызывающих вне рамок ветки. Ре-ревью: CR-101 `FormatChecks::checks()` → `allows()` (конфликт имён со статическим `FormatConstraints::checks()`); отклонено CR-105 (взаимные статические вызовы `FormatConstraints` ↔ `KindConstraints` были и до ветки; `FormatCatalog` — когда разрастётся).
- **CI гоняет полный infection, локально — по диффу (2026-10-26 UTC).** Выпуск 1.8.0 упал в CI на трёх старых мутантах вне диффа: `Keywords::typed()` `array_values` был эквивалентен (ключи перенумеровывает `unwrap()`), теперь `typed()` возвращает `array<int, Schema>`; `MemberConstraints::isScalar` для одиночного класса — тест «any of two dates» (в `oneOf` формат даты в строгой подсхеме и так отбрасывает члены, поэтому нужен `anyOf` + `maxLength`). Перед выпуском — полный `infection` (4 потока, ~5 мин), не только диффовый.

- **Строгий телефон и x-validator-format (2026-10-27 UTC).** `formats: {phone: strict}` → `FormatChecks::$strict` (только `FormatConstraints::STRICT_FORMATS` = `phone`; `strict` у другого формата — ошибка конфига; в списочной форме `strict` читается как имя формата → «does not check»). Доступность библиотеки решает **enricher один раз** (`ValidatorEnricher::formatChecks()`: `PackageVersion::atLeast(odolbeau/phone-number-bundle, 3.5)` — с 3.5 `PhoneNumber` атрибут; иначе `FormatChecks::withoutStrict()`), предупреждение — только в `enrichProperty`, если у свойства сам `format: phone` и нет `x-validator-format: false`. НЕ в `FormatConstraints`: подсхемы (`not`/`if`/`oneOf`/`anyOf`/`then`…) строятся со своим `Diagnostics`, и любое предупреждение там выкидывает всю подсхему (`ConstraintBuilder::subschema`) — ревью CR-001. `ConstraintSpec::phoneNumber()` (алиас `PhoneAssert`). Валидатор бандла создаётся и без регистрации бандла (аргументы конструктора необязательны), регион тогда `ZZ` → только `+…`. Пакет 4.x требует PHP ≥ 8.1, поэтому интеграционного теста с реальным Symfony нет. `x-validator-format` читает `ConstraintBuilder::build()` (`ExtensionReader::optionalFlag`, tri-state) и передаёт сборку производному builder'у с `FormatChecks::allSwitched(bool)` (strict сохраняется) → работает и для свойства, и для повторного объявления в потомке (`narrowings`), и для вложенных items/подсхем; схема `$ref`-цели не читается. `PackageVersion::atLeast` — общий с `RuntimeConstraints` (dev-ветка = новая).
- **Present по уровням (2026-10-27 UTC).** `narrowings()` пишет по одному `Present` на уровень цепочки: `(list_i − list_{i+1}) ∩ list_класса`, где list_0 — `requiredInherited()` класса, list_i — i-го предка (ближайший первым). Предок пишет ровно такой же `Present` сам → `enrichClass` вычитает его через `writtenBy` (сериализация), а если предок skip/в своих группах (exclusive) — у потомка остаётся. `mixed` — `Present` (как конструктор ядра), хотя собственный обязательный `mixed` без `NotNull` — задокументировано в README (ревью CR-004).
- **Отклонено в ревью 2026-10-27:** CR-005 (ветка strict в `FormatConstraints::of` общая, но пишет `PhoneNumber`: единственный strict-формат, `Settings` не пропустит другой, у константы `STRICT_FORMATS` пометка; второй формат потребует своей фабрики — YAGNI), CR-009 (предупреждение о пакете на каждом свойстве — как у `symfony/intl`, указывает каждое место с ослабленной проверкой).
