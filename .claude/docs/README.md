## Архитектура (B1)
- `SymfonyExtension` (`name()` = `symfony`) — точка входа; объявлен в `extra.dto-generator.extensions` нашего `composer.json`, ядро находит его само.
- `Settings::fromConfig()` — секция `extensionConfig.symfony`; ошибки — `InvalidArgumentException` со всеми проблемами, ядро показывает её как «Extension "symfony" failed to register: …» на `dto-generator.yaml#`.
- `SymfonyVersion` — `major.minor`; `resolve(settings, packages, component)`: конфиг → версия компонента из lock → старшая из `symfony/validator`/`symfony/serializer` → `LATEST` (8.1, проверено матрицей). `MINIMUM` = 5.4.
- deptrac: `Bridge` → только `CoreSpi` (Contract, Domain\{Model,Schema,Diagnostic,Target,Shared}) и `TypeAlias` (импортированный `JsonValue`).

## Validator (B2)
- `Validator\ValidatorEnricher` (регистрируется `SymfonyExtension`): решает «писать ли» один раз на запуск по первому свойству (предупреждения — на корне его документа): `validator: false`/`auto` без пакета → нет; `true` без пакета → warning; версия < 5.4 → warning, нет; `metadata: annotations` + validator ≥ 7.0 → strict: error / warning, нет; 5.4/6.4 без `doctrine/annotations` → warning.
- `ConstraintBuilder` — таблица §5.1 в её порядке (оркестратор, подсхемы, `All`, композиты); слова одного вида значения и форматы — `KindConstraints` (`KEYWORDS_OF`), заявленные мостом слова — `ClaimedConstraints`; `Keywords` — значения всех звеньев `$ref` (`chain()`) и веток `allOf`, каждое место один раз (AND: строже граница, все `pattern`, пересечение `enum`), `resolved()` — через единственную типизированную ветку `allOf`, как `TypeMapper::typed()` ядра; `KeywordReader` — числовые ключевые слова с проверкой; `Interval` — есть ли значение (целое) между границами; `ValueConstraints` — `enum`/`const` в PHP-типе свойства, case PHP-enum; `Pattern` — ECMA → PCRE (`/uD`), `UnicodeEscape` — `\u` и суррогатные пары; `ConstraintSpec` — имя + аргументы → атрибут с `ImportAlias(…Constraints, 'Assert')` или `new` внутри `All`. `NotNull` ставит `ValidatorEnricher`.
- Тесты — настоящий генератор ядра в dry-run на временном проекте с `composer.lock`; `attributesOf()` разбирает сигнатуру конструктора по запятым нулевой глубины.

## Serializer (B3)
- `Serializer\SerializerEnricher` — `ClassEnricher` + `PropertyEnricher` (один экземпляр, регистрируется дважды). `DiscriminatorMap` на классе с `discriminator()`; на свойстве: `Ignore` | `SerializedName`, `Groups`, `Context` (дата).
- `ComponentGate` (корень) — «писать ли» и версия для validator/serializer, один раз на запуск, диагностики на корне документа. `ExtensionReader` — `x-` флаги и списки групп. `Keywords` теперь в корне пакета.
- Тесты — трейт `Test\Unit\GeneratesDtos` (генератор в dry-run, `attributesOf()`, `classAttributesOf()`).

## Матрица (B4)
- `tests/Integration/Symfony/RealSymfonyTest` — сгенерированные DTO + настоящие Validator/Serializer; локально `tests/Integration/Symfony/run-matrix.sh '<версия>' [8.4-cli|8.5-cli]` (`LOWEST=1` — prefer-lowest). CI — задание `phpunit` стандарта по `symfony-versions`.
- `composer-ci.json`: Symfony-компоненты, `doctrine/annotations` ^2 (аннотации цели 7.4 на Symfony < 7; пакет заброшен — `config.audit.abandoned: report` во всех трёх `composer*.json`, с 2026-10-11 UTC и в `composer.json`: иначе `make check` без `COMPOSER=` падал на `composer audit`), `phpdocumentor/reflection-docblock` ^5.6.
- PHPStan (`phpVersion 70400`) не читает Symfony 8 — тест исключён в `phpstan-baseline.neon` (`excludePaths`; `phpstan -b` перезапишет файл — вернуть блок руками), вручную: `vendor/bin/phpstan analyse -c phpstan-symfony.neon`.
- `FOREIGN_DEPRECATIONS` в `RealSymfonyTest` — список устареваний Symfony, не вызванных мостом; новое устаревание проваливает тест, его надо разобрать, а не добавлять в список не глядя.
- Infection `^0.29 || ^0.32` (console 5.4 ↔ 8); 0.32 печатает только Covered Code MSI.
- Rector с установленным `symfony/validator` превращает строки FQCN в `::class` (тестам это безопасно: `::class` не загружает класс).

## Бандл (B5)
- `src/Bundle`: `DtoGeneratorBundle`, `DependencyInjection\{DtoGeneratorExtension,Configuration}`, `Command\GenerateCommand` (обёртка над `generate` ядра, свой `ArrayInput`), `CacheWarmer\GenerationCheckWarmer`. deptrac: слой `Bundle` видит только `CoreSpi` и `CoreEntry` (`DtoGenerator`, `Generate\{Input,Mode,Output,Status}`).
- Тесты — `tests/Unit/Bundle` (настоящее ядро Symfony, `TestKernel`; кэш контейнера — свой на каждый конфиг бандла, иначе ядро берёт старый контейнер). Устаревания из `vendor/` глушатся с самого начала `setUp()`: Symfony 5.4 и старые contracts на PHP 8.4 бросают их уже при загрузке классов.
- PHPStan: `phpstan-symfony.neon` (PHP 8.4) — `src/Bundle`, `tests/Unit/Bundle`, `tests/Integration/Symfony`; в основном они исключены. `make check` и задания стандарта его не запускают — это делает собственный job `Bridge checks` в `checks.yml` (PHP 8.4, `composer-ci.json`), локально вручную: `vendor/bin/phpstan analyse -c phpstan-symfony.neon`. Тот же job гоняет `phpstan-php74.neon`: запреты функций и классов PHP 8 (`customRulesetUsed: true`, `strictRules.allRules: false`, список как в ядре; `phpVersion 70400` их не ловит) — плюс правила, которые extension-installer регистрирует сам (phpstan-phpunit, composer), без baseline; `Stringable` разрешён в `tests/Unit/Bundle` — CS-Fixer шаблона импортирует его из PHPDoc тестового логгера. `phpstan.dist.neon`/`Makefile` — шаблоны стандарта, поэтому дополнительные проверки — в job, не в них.
- `GenerateCommand::run()` обёрнут в `DtoGenerator::guard()`: `CommandTester` и `Application` вызывают `run()` команды, а ошибка привязки входа (`--chek`) бросается внутри `Command::run()` — без обёртки Symfony отвечал бы 1, что у генератора значит «устарело».
- Сбой команды (код 2) не доходит до `ConsoleErrorEvent` и логгера FrameworkBundle — `guard()` ловит его внутри `run()`, вывод только в stderr, как у CLI ядра. Код 2 на уровне бандла тестом не покрыт: ядро не даёт надёжного способа упасть не-`ExceptionInterface`; сам `guard()` покрыт в ядре.
- Прогрев строит генератор ядра в `warmUp()` под `try`, а не в конструкторе: исключение при создании сервиса уронило бы весь `cache:warmup`.
- deptrac: слои моста — по namespace (`classNameRegex`), не по каталогу: `directory` ищет шаблон в любом месте абсолютного пути, и `src/` из пути checkout (`/usr/src/app`) смешал бы слои. Псевдоклассы `Json(Value|Scalar)` исключены из `Bridge` — это слой `TypeAlias`.
- Ядро требует абсолютный путь в `Generate\Input` (`InvalidArgumentException`), поэтому команда и прогрев разрешают `config` от каталога проекта сами; `--config` команды разрешает ядро — от `console($projectDir)`, т. е. тоже от проекта.

## E4 (паритет с CLI, форматы; план `docs/internal/plans/2026-10-09-e4-bridge-parity.md`)
- `GenerateCommand::run()` вызывает `DtoGenerator::prepareProcess($output)` перед `guard()`; прогрев — нет (долгоживущий процесс). Команда в долгоживущем процессе (CommandTester, Messenger `RunCommandMessage`, `Application::run()` из контроллера) оставляет ему `display_errors=stderr`, `memory_limit` ≥1G и shutdown-обработчик (код 2) — в README. `DTO_GENERATOR_MEMORY_LIMIT` из `.env` не доходит: Dotenv не делает `putenv()` с 5.0. Тесты бандла меняют `memory_limit`/`display_errors` процесса PHPUnit — `setUp()` запоминает их и `DTO_GENERATOR_MEMORY_LIMIT`, `tearDown()` восстанавливает.
- `int32`: границы `[-2147483648, 2147483647]` — кандидаты в `KindConstraints::strictest()` с меткой `format: int32` (после исключающих и включающих ключевых слов; при равенстве остаётся первый, поэтому мутант `>`→`>=` убивает существующий тест на равенство исключающей и включающей). `Range` — когда обе границы не исключающие (`!== 'exclusiveMinimum'`), иначе пара сравнений. Только для `kindOf() === 'integer'`; у `number` ядро само предупреждает «Unknown number format».
- `byte`: строка `FORMATS` (`Regex` `/^[A-Za-z0-9+\/]*+={0,2}$/D` — `D`, как у `pattern`). Линейный шаблон без повторяемой группы — решение владельца (ревью E4, CR-001): `(?:[A-Za-z0-9+\/]{4})*…` исчерпывал стек JIT PCRE (~100 КБ) или, без JIT, recursion limit (~400 КБ), `preg_match` возвращал `false`, а `RegexValidator` Symfony считал это нарушением. Звезда possessive (`*+`, ре-ревью RR-001): жадная на невалидной строке от ~1 млн символов откатывалась до «Backtrack limit exhausted». Цена — длина не проверяется на кратность 4 (`QUJ`, base64 без `=`, одиночные `=`/`==` проходят), задокументировано. В тестах — `assertSame(0|1, preg_match(...))` через хелпер `match()`: `assert(DoesNot)MatchesRegularExpression` не отличает `false` от 0, а прямой `assertSame(1, preg_match())` Rector (`AssertRegExpRector`) переписывает в них. Тест на 1 и 8 МБ с `pcre.jit` 1 и 0: PHP кэширует скомпилированный шаблон вместе с JIT, поэтому вариант без JIT берёт шаблон с игнорируемым модификатором `S` (другой ключ кэша). Минимум int32 записан `-2147483647 - 1`: литерал 2147483648 на 32-битном PHP — float. `FORMAT_KINDS` (`int32`, `byte`) — форматы одного вида: у значения нескольких типов предупреждение «"format: X" checks only …; it is not checked». Остальные форматы (`email`…) на таком значении по-прежнему молча пропускаются.
- Вывод ядра 1.2, который мост покрывает без изменений кода: смешанный `enum` → `UnionType` (kind `several`) → `Choice` с обоими видами + предупреждения для `minLength`/`minimum`; вынесенные члены `oneOf`/`anyOf` → `Valid` (по `Keywords::describesObject()`), у `list<A|B>` — тоже.
- Дискриминатор E2 на матрице (`RealSymfonyTest`): denormalize через базу, default единственного значения при denormalize прямо в вариант, иностранное значение → ровно `\InvalidArgumentException` из конструктора (Serializer ловит только `TypeError`); enum-дискриминатор (`CreatureKind`) на 8.2 — case, на 8.0/7.4 — строка. Normalize варианта с несколькими значениями mapping пишет значение свойства, а не первый ключ mapping (проверено на 8.1, в матрицу не вынесено).

## E5 (`$additionalProperties` в Serializer; план `docs/internal/plans/2026-10-10-e5-additional-properties.md`)
- `Settings::spreadsAdditionalProperties()` (`additionalProperties: ignore|spread`). `SerializerEnricher::spreads()`: `ignore` → прежний warning + `Ignore`; `spread` → маркер `Runtime\AdditionalProperties` (ядро пишет его полным именем `\Msstc4…`, без алиаса) рядом с `Groups`; цель с аннотациями → одна ошибка на запуск (флаг в экземпляре энричера), маркер всё равно пишется — файлы при ошибке не пишутся, ветка «вернуть Ignore» была бы эквивалентным мутантом. `x-serializer-ignore` на схеме значений сохраняет `Ignore`, `x-serializer-skip` — ничего.
- **Рантайм вынесен (2026-10-11 UTC)** в `msstc4symfony/dto-generator-bridge-runtime` (`../dto-generator-bridge-runtime`, тот же namespace `Msstc4Symfony\DtoGeneratorBridge\Runtime\`): атрибут, нормалайзер, `DtoGeneratorRuntimeBundle`, `Normalizers::register()` и `DropOrphanNormalizerPass`. Мост `require`ит его (`^1.0`); `DtoGeneratorExtension` вызывает `Normalizers::register()`, `DtoGeneratorBundle` добавляет его pass — определение совпадает с рантайм-бандлом, оба бандла можно включать вместе. Подробности о `mixed`/PHP 7.4, PHPStan и фикстурах — `.claude/docs` рантайма. deptrac: слой `Runtime` ловит классы пакета по namespace. `composer-local.json` берёт рантайм path-репозиторием `../dto-generator-bridge-runtime` (версия 1.0.0); `composer.json`/`composer-ci.json` — `vcs` GitHub.
- `AdditionalPropertiesNormalizer` — **декоратор** объектного нормалайзера (не флаг в контексте: флаг унаследовали бы вложенные объекты того же класса). Аргументы: `NormalizerInterface` с проверкой `DenormalizerInterface` в конструкторе (пересечение типов PHP 7.4 не разбирает), та же `ClassMetadataFactory`, name converter обёрнутого (по умолчанию `MetadataAwareNameConverter($metadata)`; бандл передаёт `serializer.name_converter.metadata_aware`, который оборачивает `framework.serializer.name_converter`). `setSerializer()` передаёт Serializer обёрнутому. Описание класса — `ClassLayout` (`@internal`): PHP-имя map, её ключ после конвертера, объявленные ключи `array<string, true>`; кэш на класс+формат (конвертер может зависеть от формата), маппинги дискриминаторов — отдельный кэш на класс/интерфейс. Объявленные ключи — имена атрибутов метаданных через конвертер плюс `typeProperty` дискриминаторов класса, родителей и интерфейсов (`ClassMetadata::merge()` не переносит маппинг в потомка). `ClassLayout::declares()` — `?? false`, не `isset`: иначе мутант `= false` в `read()` выживает. Кэши наблюдаемы — тест считает вызовы `getMetadataFor` моком фабрики. Объявлен один дискриминатор — тот, что пишет Symfony (`ClassDiscriminatorFromClassMetadata::getMappingForMappedObject()`): свой, родителя (рекурсивно), затем интерфейсы в порядке `getInterfaceNames()`, каждый со своими родителями — `mappedBy()` рекурсивен и для интерфейсов (ре-ре-ревью RRR-002). Но при чтении ключ дискриминатора **запрошенного** типа (другая база/интерфейс) тоже остаётся на верхнем уровне (`typeKeys()`): Symfony выбирает по нему вариант, а в map он бы потерялся (RRR-001, регрессия от RR-007). Ключи дискриминаторов — как `AbstractObjectNormalizer::getMappedClass()`: сначала сконвертированный, затем сам `typeProperty` (последние патчи 6.4/7.4/8.1 читают оба; 5.4, 7.0–7.3, 8.0, а также 7.4.3 и 8.1.6 — только исходный: там конвертер, переименовывающий поле типа, вместе с `defaultType` не поддержан — Symfony возьмёт тип по умолчанию, а мост раскладку по сконвертированному ключу; в README, ре-ревью R5-001), затем `getDefaultType()` (7.3+; проверка `ReflectionClass::hasMethod()` — `method_exists` PHPStan сужает до «всегда true» по установленной 8.1, а `@phpstan-ignore` конфиг `phpstan-php74.neon` считает лишним). Объявлены оба ключа; конвертируются от запрошенного типа, как в Symfony (R4-001, R4-002). Тест на сконвертированный ключ пропускается, где сам Serializer его не читает. Выбор варианта — `target()`: класс + ключи типа. Конвертер вызывается без контекста: имена по контексту (группам) не поддерживаются (README). Ключ кэша — `serialize([$class, $format])` (не путает `null` и `''`). `getSupportedTypes()` = `['object' => false]`.
- Бандл: сервис регистрирует `DtoGeneratorExtension::load()` без приоритета (литералы приоритетов дали бы эквивалентных мутантов) и только при `class_exists(WeakMap::class)` (PHP 8.0, полифилла нет) — **не** `class_exists(Attribute::class)` и не сравнение версий: `version_compare(PHP_VERSION, '8.0', '>=')` Rector с набором PHP 7.4 сворачивает в false и **удаляет блок**, а у `PHP_VERSION_ID >= 80000` Infection в CI (там тесты бандла укладываются в таймаут) оставляет эквивалентного мутанта `> 80000`: `symfony/polyfill-php80` объявляет `Attribute` и на 7.4, а нормалайзер там не загружается (`mixed` сужает нетипизированный параметр интерфейса 5.4 → фатальная ошибка). При выключенном сериализаторе приватный сервис никто не использует, контейнер удаляет его вместе со ссылками (`RemoveUnusedDefinitionsPass` идёт раньше `CheckExceptionOnInvalidReferenceBehaviorPass`). Но при `serializer` без `property_access` FrameworkExtension удаляет `serializer.normalizer.object` (ре-ревью RR-001), а наш сервис с тегом уже в цепочке — поэтому `DependencyInjection\CompilerPass\DropOrphanNormalizerPass` (BEFORE_OPTIMIZATION, priority 1 — раньше `SerializerPass` с 0) удаляет определение, если обёртываемого сервиса нет. Тег без атрибута `serializer` — только сериализатор по умолчанию (именованные 7.2+ — вручную, в README). Мутанты `src/Bundle` локально Infection пропускает по таймауту (загрузка ядра Symfony), **а в CI — нет**: проверять их локально копией `infection.json5` с `timeout: 120` и `--filter=src/Bundle/`. Пустой `parent::build()` в `DtoGeneratorBundle` — эквивалентный мутант, его там нет.
- **Infection и тесты ядра Symfony:** тест бандла, загружающий ядро, покрывал бы код рантайма, и Infection пропускал бы мутанты по таймауту (ре-ревью RR-002), поэтому `testSpreadsAdditionalPropertiesInTheApplicationsSerializer` — `@coversNothing`. Фикстура `Box` — `tests/Unit/Bundle/Fixture`.
- Map объектов (`array<array-key, T>`) не читают Serializer 5.4 и 7.4.0 (ячейка prefer-lowest CI), объявленный или раскладываемый; `RealSymfonyTest` проверяет это пробой на схеме `Shelter` и пропускает часть с `Kennel`, а не по номеру версии.
- Группы Symfony действуют и на значения map (у `Owner::$name` нет группы — `['vet' => []]`).

## F1 ядра (модели чтения и записи, 2026-10-10 UTC)
- Кода в мосте нет: представления `…Read`/`…Write` — обычные классы. `RealSymfonyTest::generate($php, $variant)`: `''` | `spread` | `views`; ключ `dto.readWriteModels` пишется **только** для `views` — ядро 1.2 (VCS-тег в CI) отвергает неизвестный ключ `dto`. `testReadsAndWritesThroughTheReadAndWriteModels` пропускается без `Application\Config\ViewSuffixes` (ядро < 1.3). ## Известные особенности
- **Roave BC check** (job `standard / BC check`) сравнивает с последним тегом и пропускает класс, только если `@internal` стоит в *старой* версии. Помощники валидатора (`Keywords`, `Validator\*` кроме `ValidatorEnricher`) помечены `@internal` с 1.3.0 (2026-10-13 UTC); до тега v1.3.0 проверка на main красная из‑за `ConstraintBuilder::__construct` и `Keywords::narrowsEnum()`. Новый класс-помощник — сразу `@internal`.

## Режим build (2026-10-11 UTC, спецификация `docs/internal/specs/2026-10-11-runtime-and-build-mode-design.md` §3)

- `dto_generator.mode: committed|build` (`Configuration::COMMITTED/BUILD`); `build` + `check_on_warmup: true` — ошибка конфигурации.
- Генерация — `Bundle\DependencyInjection\CompilerPass\BuildDtosPass` (BEFORE_OPTIMIZATION, приоритет 100: раньше `RegisterControllerArgumentLocatorsPass` и прочих проходов FrameworkBundle с приоритетом 0). Не в расширении: `MergeExtensionConfigurationContainerBuilder::addCompilerPass()` бросает исключение, а `ContainerBuilder::log()` требует проход. Расширение лишь кладёт параметры `dto_generator.build.config` / `.root` (`%kernel.build_dir%/dto-generator`).
- Ядро: `Input::withOutputRoot()->withoutFetching()`; `Output::documents()` → `FileResource`, `remoteCache()` → `DirectoryResource`; `classes()` → параметр `dto_generator.build.classes` и `Bundle\Build\ClassMapLoader::add()` (сразу в проходе — для следующих проходов — и в `DtoGeneratorBundle::boot()`). Загрузчик один на процесс — callable `[ClassMapLoader::class, 'load']` (spl дедуплицирует его; статические замыкания на PHP 8.4 тоже совпадают, флаг «уже зарегистрирован» был эквивалентным мутантом), первым в очереди (`prepend`), с объединёнными картами (новый файл побеждает для того же класса, классы других ядер процесса сохраняются): `cache:clear` грузит старый контейнер и собирает новый в том же процессе — иначе старый загрузчик отдавал старые файлы. Класс, загруженный до сборки из другого файла, — предупреждение в журнале компилятора. Проход проверяет статус до ресурсов (`FileResource` несуществующего конфига бросает).
- `boot()`: `$this->container ?? null` — в Symfony 6.1+ типизированное свойство не инициализировано до `setContainer()`; прямое чтение бросает `Error`.
- Команда в режиме build передаёт ядру `--output-root` (опция CLI ядра 1.3) и может скачивать удалённые документы — так наполняется кэш для сборки без сети.
- Тесты: проход — на голом `ContainerBuilder` (`BuildDtosPassTest`, быстрый, для Infection), ядро Symfony — `@coversNothing` в `DtoGeneratorBundleTest`; каждый тест, загружающий классы, берёт уникальный namespace (`uniqueNamespace()`), т. к. класс грузится в процесс один раз.
- Мост требует ядро `^1.3` (до релиза 1.3 CI моста не соберётся — `composer-local.json` берёт ядро path-репозиторием с версией 1.3.0).

- Ветку `feat/build-mode` нельзя влить до тегов рантайма 1.0.0 и ядра 1.3.0: `composer.json`/`composer-ci.json` требуют `^1.0`/`^1.3` при `minimum-stability: stable`.

## `format: uri` / `time` (2026-10-12 UTC)

- Паттерны — `Validator\FormatPatterns` (`@internal`, `BASE64`/`URI`/`TIME` собраны из приватных констант-частей), тесты — `FormatPatternsTest` (с JIT и без, `pcre.backtrack_limit` фиксируется 1 000 000). В `URI` повторяются только классы символов (`*+`) и группа `(?:%XX[класс]*+)*+` — по итерации на `%XX`. Отвергнутые варианты: `(?:pchar|%XX)*+`, `(?:/segment)*+` — false на 8 МБ с JIT; lookahead `(?![\s\S]*%(?!XX))` — `Backtrack limit exhausted`. Предел: ~500 000 `%XX` с JIT, ~1 млн без (JIT тратит лимит вдвое быстрее). Userinfo — под lookahead `(?=[^@\/?#\[\]]*+@)`, иначе host без `@` сканировался дважды (предел host был 250 000). Високосная секунда: UTC — только `23:59:60`; смещение целыми часами — минута 59; смещение с минутами — любые. Rector переписывает `assertSame(0|1, preg_match())` в `assertMatchesRegularExpression`, который не отличает false от 0 — поэтому хелпер `match()` в `FormatPatternsTest`.
- Эмиттер ядра экранирует в атрибуте только `'` и `\` перед ними; длинную аннотацию переносит: `@Assert\Regex(\n *     pattern="…"\n * )`. Тесты вывода сравнивают с `FormatPatterns::*` (в атрибуте `'` → `\'`).
- `tests/Integration/Symfony/run-matrix.sh`: `RUNTIME` (по умолчанию `../dto-generator-bridge-runtime`) — второй path-репозиторий; версии — ближайший тег из HEAD или `CORE_VERSION`/`RUNTIME_VERSION`; все три дерева копируются `copy_tree` (рабочее дерево, включая неотслеживаемые файлы). Пропуски на Symfony 7/8 (7 шт.) — цели PHP 7.4 (аннотации).

## G1: `dependentRequired`, `propertyNames`, `contains` (2026-10-12 UTC, спека `docs/internal/specs/2026-10-12-g-validation-keywords-design.md`)

- Пишутся constraint'ы рантайма 1.1 (`RuntimeAssert` = `…\Runtime\Constraints`, `ConstraintSpec::runtime()`). Мост требует ядро ^1.4 (`ExtensionRegistry::claimKeywords()`) и рантайм ^1.1 — **влить ветку можно только после тегов ядра 1.4.0 и рантайма 1.1.0** (CI берёт их из VCS). Локально `composer-local.json` — версии path 1.4.0/1.1.0; матрица — `CORE_VERSION=1.4.0 RUNTIME_VERSION=1.1.0 tests/Integration/Symfony/run-matrix.sh …`.
- `ClaimedConstraints::KEYWORDS` заявляются (`SymfonyExtension`), если `validator` не `false`. Ядро держит вхождения в `KeywordChecks` и после обогащения предупреждает о неотмеченных: мост обязан отмечать (`ClaimedConstraints::markClaimed()`, `ValidatorEnricher::markChecked()`) каждое место, которое проверил **или** о котором сам предупредил. Неотмеченными остаются слова рядом с `$ref` на класс, `x-validator-skip` (свойства или класса), отключённый валидатор — о них говорит ядро; одиночные `minContains`/`maxContains` без `contains` в том же месте — предупреждение моста.
- Подсхему строит отдельный `ConstraintBuilder` со своими `Diagnostics`: общие склеивают одинаковые сообщения в одном месте, и счётчик не замечал повтор (re-review M3). Вложенные композиты в `All` получают группы свойства (`ConstraintSpec::isComposite()`): Symfony фиксирует группы вложенного композита при его создании.
- `ValidatorEnricher` — ещё и `ClassEnricher`: `DependentRequired` на классе; ключевые слова класса хранятся по FQCN (`$classes`: `ClassKeywords` — Keywords, место, группы класса, шаблоны `patternProperties`) для `Keys` на `$additionalProperties` — ядро обогащает класс до свойств (контракт ядра 1.4). `Keys` класса не снимается `x-validator-skip` схемы значений и берёт группы класса.
- `Subschema`: плоская схема, элементы-скаляры (G2: ещё PHP-enum и `mixed`, см. ниже; иначе только аннотации), `type` не уже PHP-типа (без учёта null; nullable-элементам при схеме, отвергающей null, — `NotNull`). Любое предупреждение собственных `Diagnostics` подсхемы = constraint не пишется (частичная проверка ошибочна в обе стороны при `maxContains`). Предупреждения подсхемы идут на место, которое её держит (`…/allOf/1`, цель `$ref`).
- Члены `oneOf`/`anyOf` с несколькими значениями (`Keywords::unreachedMembers()`), если не классы: мост предупреждает на схеме значения (свойство или его `items`) и отмечает их ключевые слова, обходя все места члена рекурсивно (`allOf`, вложенные объединения; член, чья схема — класс (свои `properties`, или объект без объединения), пропускается: его проверяет обогащение класса; в объединении места-классы пропускаются по месту; посещённые члены запоминаются — ядро обогащает модель и после ошибок, а петля через класс вообще не ошибка) — иначе общий компонент, проверенный через другое свойство, молча терялся бы (re-review m-A).
- `contains` — по местам (`Keywords::schemas()`), `minContains`/`maxContains` своего места (`KeywordReader::count()`).
- `DependentRequirements`: пара с унаследованным свойством молчит, только если место, объявляющее оба свойства, перечисляет её (`leftToTheDeclaringClass`); триггер с не-null default — предупреждение. Имя, объявленное где-то, но не своё, у класса без родителя (например, `x-php-skip`) — «not a property».
- `RuntimeConstraints` (рантайм ≥ 1.1 в lock, `dev-*` — новый) оставлен, хотя Composer и так требует ^1.1: lock проекта может отставать.
- Тестовый двойник `ExtensionRegistry` в `SymfonyExtensionTest` реализует `claimKeywords()`.

## G2: `patternProperties`, `if`/`then`/`else` (2026-10-12 UTC, спека `docs/internal/specs/2026-10-12-g2-pattern-properties-conditionals-design.md`)

- Рантайм (та же невыпущенная 1.1): `PatternProperty`, `IfThenElse` (+ `Property`, `Present` для класса). Ветки `IfThenElse` — внутренний `Conjunction` (до Symfony 7.3 у `Composite` одна опция). Symfony 8 проверяет, что всё внутри классового композита — классовое: `Property::getNestedConstraints()` возвращает `[]`.
- `ConstraintBuilder::subschema(keyword, value, place, type, nullIsAbsent)` — общий для `contains`/`propertyNames`/шаблонов/веток; `asNew()` — перевод в `new` с проверкой PHP 8.1. `nullIsAbsent` (свойство класса, ветки условия): `NotNull` не добавляется — там `null` значит «нет значения» (и `IfThenElse`/`Property` пропускают `null`).
- `Subschema` для PHP-enum: только `type`/`const`/`enum`; `enum` на PHP-enum → `Choice` из констант случаев, если сужает (`ValueConstraints::enumCases()`; прежнее предупреждение «One enum narrows another» и `Keywords::narrowsEnum()` удалены). Для `mixed`: `type` даёт `Assert\Type` (`number` → `['int', 'float']`), слова строк/чисел — только при одном типе из string/integer/number/boolean, сборка идёт для этого `ScalarType`.
- Условия значения — в `ClaimedConstraints::conditions()` (первая непроверяемая ветка обрывает чтение: одно предупреждение); класса — `ClassConditions` (ветки только `properties`/`required`, имена — свои свойства; default под `properties` или в `if.required` — предупреждение; наследование — как у `dependentRequired`). Имена держатся списком пар, не ключами массива: числовое имя «7» стало бы int-ключом (Rector снимает `(string)` у `array_key_first`).
- `patternProperties` значения (map) — `ClaimedConstraints::patterns()`; класса — `ValidatorEnricher::patterns()` (предупреждения: нет `$additionalProperties`; схема `additionalProperties` типизирует и совпавшие ключи — `PatternSchema::ALSO_ADDITIONAL`) и `classConstraints()`: объявленному свойству, чьё проводное имя совпало с шаблоном при генерации, — constraint'ы подсхемы (группы класса), `$additionalProperties` — `PatternProperty`.
- Тесты: `ConditionalsTest`, `PatternPropertiesTest`; `RealSymfonyTest::testChecksConditionsAndPatternProperties` (схема `Parcel` в `api.yaml`). `GeneratesDtos::attributesOf()/classAttributesOf()` разбирают вложенность скобок любой глубины (рекурсивный PCRE).

- Ревью G2 (2026-10-12 UTC): подсхема «только null» (`type: null`, `enum: [null]`) — `IsNull` (`Subschema::admitsOnlyNull()`), иначе пустой список constraint'ов читался бы как «всё подходит». У `mixed` целое число в `const`/`enum` при `type`, допускающем float (нет `type` или есть `number`), — предупреждение: JSON `0` декодируется в int, `0.0` — во float, а `IdenticalTo`/`Choice` их различают. Шаблон потомка, совпавший с унаследованным свойством, — предупреждение (`ValidatorEnricher::warnAboutInheritedMatches()`: цели всех `$ref` из `allOf` на любой глубине (`targets()`, сами цели, без соседей `$ref`); молчит, только если шаблон лежит в местах каждой цели, достигающей объявления свойства, — значит, в самой узкой, из которой сгенерирован класс-владелец. Объявление, которого не достигает ни одна цель, не унаследовано (`x-php-skip`); свои свойства, в том числе слитые из нескольких `$ref`, пропускаются. CR-101/CR-201). На цели без PHP-enum `EnumType` в подсхеме идёт как его скаляр (`ConstraintBuilder::withoutEnums()`). Решения — §5 спеки G2.

## Разбиение `ConstraintBuilder` (2026-10-13 UTC, CR-013 G2)

- `ConstraintBuilder` (порядок §5.1, `subschema()`, `asNew()`, `condition()`, `elements()`; делегаты `names()`/`patternProperties()` для `ValidatorEnricher`), `KindConstraints` (строки, числа, коллекции, форматы; `@phpstan-type Kind`/`Bound`/`ImpliedBound`), `ClaimedConstraints` (`contains`, `propertyNames`, `patternProperties`, `if`/`then`/`else`, члены `oneOf`/`anyOf`; `KEYWORDS`, `conditionPlaces()`). `KeywordReader::consistent()` — min ≤ max для счётчиков (место и `Diagnostics` читателя).
- `ClaimedConstraints` держит обратную ссылку на свой `ConstraintBuilder` (ему нужны `subschema()`/`asNew()`/`condition()`); у каждого строителя подсхемы — свой `ClaimedConstraints` с одноразовыми `KeywordChecks`. Цикл ссылок собирает GC — для генерации неважно (ревью: интерфейс ради одной реализации и разрыв цикла отклонены).
