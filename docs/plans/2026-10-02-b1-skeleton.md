# dto-generator-bridge-symfony — этап B1: каркас и расширение. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Пакет устанавливается рядом с ядром, ядро обнаруживает `SymfonyExtension`, секция `extensionConfig.symfony` разбирается, версия Symfony определяется по `InstalledPackages`.

**Spec:** `docs/specs/2026-10-02-bridge-symfony-design.md` §2, §3, §9 (B1).

## Global Constraints
PHP ≥ 7.4; PHPStan max (phpVersion 70400), CS-Fixer, Rector, deptrac, infection MSI 100 % — как у ядра. Ядро подключено path-репозиторием `../../msstc4php/dto-generator` (`dev-main`).

## Решения
- Слои deptrac: `Bridge` (`src/`, кроме `Bundle`) зависит только от SPI ядра (`Contract`, `Domain\Model`, `Domain\Schema`, `Domain\Diagnostic`, `Domain\Target`); `Bundle` появится в B5.
- `Settings::fromConfig(array)` — неизменяемый разбор секции; неизвестный ключ или неверный тип → `InvalidArgumentException` с путём `extensionConfig.symfony.<key>` (ядро выводит её как ошибку регистрации).
- `SymfonyVersion` — `major.minor`; `fromPackageVersion('v6.4.1')` → 6.4, нечисловая (`dev-main`) → null; `resolve(Settings, InstalledPackages)`: явная версия, иначе старшая из `symfony/validator`/`symfony/serializer`, иначе 7.0.
- `SymfonyExtension` в B1 регистрирует только `claimExtensionKeys('x-validator-*', 'x-serializer-*')`; enricher'ы — в B2/B3.

## Tasks
1. Каркас: `composer.json` (path-репозиторий, `extra.dto-generator.extensions`), `tools/`, конфиги инструментов, Makefile, CI.
2. `Settings`, `SymfonyVersion`, `SymfonyExtension` с тестами; функциональный тест: ядро с мостом генерирует без ошибок и отклоняет неверную секцию.

## Решения при выполнении (журнал)
- Ruling: `LATEST` = 7.4 (последняя версия, правила которой мост знает), минимум 5.4; версия ниже 5.4 в конфиге — ошибка — цена ошибки: при 8.x мост пишет как для 7.4 до B4.
- Ruling: версия определяется по компоненту (`resolve(..., 'symfony/validator')`), иначе старшая из остальных — компоненты версионируются независимо.
- Ruling: ошибки секции идут через исключение из `register()`; ядро показывает их на корне конфига, поэтому сообщение само называет ключ; все проблемы — в одном сообщении. Изменять ядро ради точного места не стали — цена: место ошибки менее точное.
- Ruling: `Settings` в B1 только проверяется; хранить и передавать enricher'ам — в B2.
- Ruling: `SymfonyVersion` хранит `int` без `non-negative-int`: регулярка гарантирует цифры, а `max(0, …)` дал бы только эквивалентные мутанты.
