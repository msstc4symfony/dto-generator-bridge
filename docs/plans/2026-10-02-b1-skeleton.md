# dto-generator-bridge-symfony — этап B1: каркас и расширение. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Пакет устанавливается рядом с ядром, ядро обнаруживает `SymfonyExtension`, секция `extensionConfig.symfony` разбирается, версия Symfony определяется по `InstalledPackages`.

**Spec:** `docs/specs/2026-10-02-bridge-symfony-design.md` §2, §3, §9 (B1).

## Global Constraints
PHP ≥ 7.4; PHPStan max (phpVersion 70400), CS-Fixer, Rector, deptrac, infection MSI 100 % — как у ядра. Ядро подключено path-репозиторием `../dto-generator` (`dev-main`).

## Решения
- Слои deptrac: `Bridge` (`src/`, кроме `Bundle`) зависит только от SPI ядра (`Contract`, `Domain\Model`, `Domain\Schema`, `Domain\Diagnostic`, `Domain\Target`); `Bundle` появится в B5.
- `Settings::fromConfig(array)` — неизменяемый разбор секции; неизвестный ключ или неверный тип → `InvalidArgumentException` с путём `extensionConfig.symfony.<key>` (ядро выводит её как ошибку регистрации).
- `SymfonyVersion` — `major.minor`; `fromPackageVersion('v6.4.1')` → 6.4, нечисловая (`dev-main`) → null; `resolve(Settings, InstalledPackages)`: явная версия, иначе старшая из `symfony/validator`/`symfony/serializer`, иначе 7.0.
- `SymfonyExtension` в B1 регистрирует только `claimExtensionKeys('x-validator-*', 'x-serializer-*')`; enricher'ы — в B2/B3.

## Tasks
