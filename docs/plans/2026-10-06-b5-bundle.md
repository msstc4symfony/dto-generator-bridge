# dto-generator-bridge — этап B5: бандл Symfony. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** приложение Symfony подключает `DtoGeneratorBundle` и получает команду `dto-generator:generate` и необязательную проверку актуальности DTO при прогреве кэша.

**Spec:** `docs/specs/2026-10-02-bridge-symfony-design.md` §7.

## Global Constraints
`src/` — PHP 7.4; бандл работает на Symfony 5.4–8 (5.4 — единственная линия для PHP 7.4); Symfony не входит в `require` моста — генератору бандл не нужен.

## Решения
- **Классы** (`src/Bundle`): `DtoGeneratorBundle` (классический `Bundle` — `AbstractBundle` появился в 6.1), `DependencyInjection\DtoGeneratorExtension` и `Configuration` (`config`, `check_on_warmup`), `Command\GenerateCommand`, `CacheWarmer\GenerationCheckWarmer`. Сервисы регистрируются кодом в `Extension::load()`, без файлов конфигурации — одинаково на 5.4–8.
- **Команда** берёт определение и поведение у команды `generate` ядра (`DtoGenerator::console($projectDir)->find('generate')`): те же опции, вывод и коды выхода; если `--config` не задан, подставляется `dto_generator.config`. Имя задаётся конструктором (`$defaultName` удалён в 8), тег `console.command` с `command` — ленивая загрузка.
- **Прогрев:** при `check_on_warmup: true` — `kernel.cache_warmer` (необязательный): генерация в режиме `check`, при расхождении или ошибке — warning в логгер (`logger`, иначе `NullLogger`); файлы не пишет. `warmUp($cacheDir, $buildDir = null): array` без нативных типов параметров — совместим с сигнатурами 5.4–8.
- **deptrac:** слой `Bundle` может использовать вход ядра (`DtoGenerator`, `Application\Service\Generate\{Input,Mode,Output,Status}`), SPI и Symfony; остальной мост бандл не видит.
- **Тесты:** `tests/Unit/Bundle` — настоящее ядро Symfony (`Kernel` + `FrameworkBundle` + бандл) во временном проекте: команда (`--check`, `--dry-run`, запись, `--config` по умолчанию), прогрев (warning при устаревших DTO, тишина при актуальных, нет сервиса при `false`). Без `framework-bundle` тест пропускается.

## Решения при выполнении
- Ruling: ядру передаётся новый `ArrayInput` с опциями из его определения — `Command::run()` заново привязывает вход, и подставленный `--config` терялся.
- Ruling: код бандла (`src/Bundle`) исключён из основного PHPStan и проверяется `phpstan-symfony.neon` на PHP 8.4 — `phpVersion 70400` не читает Symfony 8 (классы «unknown», нативный `mixed` — класс); `phpstan.dist.neon` — шаблон стандарта. Стоимость: CI стандарта этот конфиг не запускает — проверка ручная, как у теста матрицы.
- Ruling: тесты бандла — в наборе `unit`, чтобы Infection (он гоняет только `unit`) покрывал `src/Bundle`; без Symfony они пропускаются.
- Ruling: `setInteractive()` не переносится — команда ядра ничего не спрашивает.

## Ревью high (MA-1…S-5) — исправления
- MA-1: относительный `config` разрешается от `%kernel.project_dir%` (`Path::resolve` ядра) и в команде, и в прогреве; прогрев ловит `Throwable` → warning (тест через подставной генератор — необязательный 4-й аргумент конструктора).
- MA-2: ядро получило `DtoGenerator::guard()` (слито в `main` ядра); `GenerateCommand::run()` идёт через него — `--chek` → 3, JSON при `--format=json`.
- MA-3: README — регистрация `['dev' => true, 'test' => true]` для установки `--dev`; прогрев в проде требует моста в `require`.
- MA-4: deptrac — слои `Bundle` (`src/Bundle`) и `CoreEntry`; `Bridge` — `src/` без `Bundle`.
- MI-1…MI-5: справка `--config` показывает конфиг бандла; пустой `--config` его не сбрасывает; README о разрешении путей; тест «нет warmer'а» проверяет наличие `test.service_container`; тесты относительного конфига, настоящего `cache:warmup`, все ядра тестов закрываются в `tearDown()`.
- MI-6: ручная проверка `phpstan-symfony.neon` описана в `.claude/docs`.
- S-1…S-5: `description` в теге `console.command` (тест сверяет с описанием ядра); `conflict` `symfony/framework-bundle <5.4`; формулировка `info()`; фильтр устареваний пропускает к PHPUnit устаревания ядра (`vendor/msstc4php`); путь тестов в плане.
- Ruling: аргументы определения ядра не копируются — их нет, а строка давала выжившего мутанта; вход ядру и так собирается только из опций.

## Повторное ревью medium — исправления
- CR-001: пустое значение отбрасывается только у `--config`; `--format=` уходит ядру и даёт 3.
- CR-002: слои `Bridge`/`Bundle` — по namespace, не по каталогу (шаблон `directory` не якорится и видит путь checkout).
- CR-003: генератор ядра строится в `warmUp()` под `try`.
- CR-004: все ядра тестов — через `bootedKernel()`/`command()` и закрываются в `tearDown()`.
- CR-005/CR-006: в `.claude/docs` — сбой команды не идёт в логгер Symfony (паритет с CLI); код 2 на уровне бандла не покрыт тестом. Ruling: подходящего сбоя ядро не даёт, `guard()` покрыт в ядре — стоимость: регресс обёртки для кода 2 поймает только тест на код 3 (тот же `run()`).
- CR-007: пустой список ошибок — в сообщении статус.
- CR-008: аргумент генератора помечен в PHPDoc как внутренний, для тестов.
