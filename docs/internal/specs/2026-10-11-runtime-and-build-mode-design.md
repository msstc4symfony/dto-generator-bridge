# Рантайм-пакет и режим сборки DTO при развёртывании

**Дата:** 2026-10-11 (UTC). **Статус:** одобрено владельцем 2026-10-11 («давай сделаем отдельную репу для
рантайм-пакета… mssrc4symfony/dto-generator-bridge-runtime»; «делай как предложил» — про режим 2). Имя вендора —
`msstc4symfony` (в сообщении опечатка).

## 1. Проблема

Генератор и мост задуманы для разработки: DTO генерируются и коммитятся, оба пакета — в `require-dev`. Но при
`extensionConfig.symfony.additionalProperties: spread` сгенерированный код ссылается на атрибут
`Msstc4Symfony\DtoGeneratorBridge\Runtime\AdditionalProperties`, а приложению нужен `AdditionalPropertiesNormalizer`:
мост приходится ставить в `require`, а с ним — весь генератор.

Второй сценарий: DTO не коммитятся, а собираются при сборке приложения (`cache:warmup`, сборка контейнера).

## 2. Режим 1 (основной): DTO в репозитории, рантайм отдельно

Новый пакет `msstc4symfony/dto-generator-bridge-runtime`, репозиторий `github.com/msstc4symfony/dto-generator-bridge-runtime`
(публичный, как остальные; не на Packagist — подключается как `vcs`, как мост и ядро), каталог
`~/PhpstormProjects/msstc4symfony/dto-generator-bridge-runtime`. Соответствует `bundle-standard` (профиль `php74`).

- **Пространство имён прежнее:** `Msstc4Symfony\DtoGeneratorBridge\Runtime\` → `src/`. Сгенерированный код и
  пользователи нормалайзера не меняются; PSR-4 Composer допускает вложенный префикс в другом пакете.
- **Содержимое:** `AdditionalProperties`, `AdditionalPropertiesNormalizer`, `ClassLayout` (переезжают из моста как
  есть) и бандл `Runtime\Bundle\DtoGeneratorRuntimeBundle`: регистрирует нормалайзер (PHP 8.0+, как сейчас мост) и
  проход, убирающий его без `serializer.normalizer.object`. Регистрация — публичный `@internal`-помощник пакета,
  который вызывает и мост.
- **Зависимости:** `php >=7.4` (пакет должен ставиться рядом с мостом на 7.4; нормалайзер грузится только на 8.0+),
  без генератора. `symfony/serializer` и `symfony/framework-bundle` — в `suggest`; конфликты — как у моста.
- **Тесты:** юнит- и интеграционные тесты нормалайзера переезжают из моста (матрица Symfony 5.4/6.4/7.4/8), Infection
  100 %.
- **Мост (1.2):** `require` рантайм-пакета `^1.0`, удаляет `src/Runtime`, регистрирует нормалайзер через помощник
  рантайма — для тех, кто держит мост в `require` и не включил рантайм-бандл, ничего не меняется. Определение
  одно и то же (тот же id), поэтому включённые вместе бандлы не дублируют сервис.
- **Документация:** установка для режима 1 — `require` рантайма, `require-dev` моста, в `bundles.php`
  `DtoGeneratorRuntimeBundle` для `all`, `DtoGeneratorBundle` для `dev`/`test`.

## 3. Режим 2 (по желанию): сборка при сборке контейнера

Конфиг моста: `dto_generator.mode: committed|build` (по умолчанию `committed` — текущее поведение).

- **Когда:** при сборке контейнера — compiler pass `BuildDtosPass` (BEFORE_OPTIMIZATION, приоритет 100, раньше
  проходов FrameworkBundle, разбирающих сигнатуры контроллеров), не в прогреве кэша: прогрев идёт после компиляции,
  и встроенные прогревы валидатора/сериалайзера могут пройти раньше нашего. Не в расширении: оттуда нельзя добавить
  проход и писать в журнал компилятора. Загрузка `src/` как сервисов идёт раньше — свои классы не должны наследовать
  сгенерированные.
- **Куда:** `%kernel.build_dir%/dto-generator/`, каталог каждого источника — его `outputDir` относительно каталога
  конфига (выход за каталог конфига — ошибка конфигурации). Исходники проекта не трогаются.
- **Ядро (1.3):** `Generate\Input` получает `withOutputRoot(string $dir)` (перенос `outputDir` под корень) и
  `withoutFetching()` (удалённые `$ref` — только из кэша); `Output` сообщает классы сгенерированных файлов
  (класс → путь) для загрузчика.
- **Пересборка:** спецификации и прочитанные документы — ресурсы контейнера: в dev правка YAML пересобирает
  контейнер и DTO. Ошибка генерации останавливает сборку контейнера с диагностикой ядра; предупреждения — в лог
  сборки (`ContainerBuilder::log`).
- **Автозагрузка:** класс-карта — параметр контейнера; один загрузчик на процесс, первым в очереди, с последней
  картой (`ClassMapLoader::replace()` в проходе и в `boot()`): `cache:clear` грузит старый контейнер и собирает новый в
  том же процессе. Совместимо с `--classmap-authoritative`.
- **Сеть:** не используется; документы удалённых `$ref` должны быть в закоммиченном кэше.
- **Команда** `dto-generator:generate` в режиме `build` пишет туда же (`--output-root` CLI ядра). Кэш удалённых
  документов при отсутствии контейнера наполняет CLI ядра: `vendor/bin/dto-generator generate --output-root=…`.
- `check_on_warmup: true` с `mode: build` — ошибка конфигурации (сверять нечего).
- **Цена режима:** генератор и мост — в `require`; IDE/PHPStan не видят классов без локальной сборки
  (`scanDirectories: [var/cache/dev/dto-generator]`); изменения DTO не видны в ревью. Документация рекомендует
  режим 1.

## 4. Этапы

1. **R1.** Новый репозиторий рантайма (перенос классов и тестов, бандл, CI по стандарту), первый релиз — по
   команде владельца.
2. **R2.** Мост на рантайме (удаление `src/Runtime`, помощник регистрации, документация установки).
3. **M1.** Ядро: `withOutputRoot`, `withoutFetching`, класс-карта в `Output`.
4. **M2.** Мост: `mode: build` — генерация в расширении, ресурсы, загрузчик, команда, проверки конфига, документация.

Релизы (теги) — только по команде владельца. До релиза рантайма мост в CI берёт его из `vcs` по ветке `main`
(`dev-main`).

## 5. Вне рамок

- Symfony Flex-рецепт (регистрация бандлов вручную, как у остальных пакетов `msstc4symfony`).
- Генерация в прогреве кэша без пересборки контейнера.
