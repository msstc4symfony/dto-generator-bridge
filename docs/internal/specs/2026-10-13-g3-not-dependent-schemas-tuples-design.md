# G3 — проверка `not`, `dependentSchemas`, `prefixItems` и `unevaluatedItems`

**Дата:** 2026-10-13 (UTC). **Статус:** владелец выбрал G3 («давай 2 + 3 + 4»); решения приняты автономно. Дополняет G1
(`2026-10-12-g-validation-keywords-design.md`) и G2 (`2026-10-12-g2-pattern-properties-conditionals-design.md`): заявки
ядра, гейт рантайма, `Subschema`, `ClassConditions` и правило «не проверить целиком — не пишем и предупреждаем»
остаются прежними.

## 1. Рантайм 1.2

- `Not(array $constraints = [], ?string $message = null, ?array $groups = null)` — на свойстве и на классе. Значение,
  прошедшее все вложенные (отдельная проверка, как `if`), — нарушение «This value is not allowed.»
  (`Not::NOT_ALLOWED_ERROR`); без вложенных нарушение у любого значения. `null` не проверяется. Группы — как у
  `IfThenElse`.
- `dependentSchemas` новых constraint'ов не требует: `IfThenElse` с `Present` в `if`.

## 2. Мост

- `ClaimedConstraints::KEYWORDS` += `not`, `dependentSchemas`, `prefixItems`, `unevaluatedItems`.
- **`not` у значения** (скаляр, enum, `mixed`): подсхема (`nullIsAbsent`: `null` — отсутствие) → `Not`. Подсхема без
  проверок (`{}`, `true`, только аннотации) даёт `Not` без вложенных: значение должно отсутствовать. `not: false` ничего
  не запрещает — место отмечается молча. `not: {type: 'null'}` (подсхема «только null») — предупреждение: `null` — это
  отсутствие, которого `Not` не видит.
- **`not` у класса** — ветка как в `ClassConditions` (`properties` → `Property`, `required` → `Present`); имена — свои
  свойства, наследование — как у условий; default под `properties` или в `required` — предупреждение (как у `if`).
- **`dependentSchemas` у класса**: для каждого имени — `IfThenElse(if: [Present([имя])], then: ветка)`; схема `false` —
  `Not([Present([имя])])`; схема без проверок — ничего. Имя и имена ветки — свои свойства (иначе, как у условий,
  предупреждение или молчаливая передача классу-владельцу); у имени-триггера с default — предупреждение (DTO не отличит
  отсутствие). У значения, не являющегося классом, — предупреждение «checked on classes only».
- **`prefixItems` у списка**: `Collection(fields: {i: [...]}, allowExtraFields: true, allowMissingFields: true)` на
  каждое место; элементы, чья подсхема ничего не проверяет, не пишутся; подсхема элемента — для типа элементов списка.
  `items` рядом (в любом месте значения) — предупреждение: сгенерированный тип даёт его всем элементам, а он действует
  только после префикса (`items: true` ядро разбирает в пустую схему, `items: false` отвергает ошибкой). Не список —
  предупреждение. Под группами значения элементы пишутся в `Optional([...], groups: [...])`: `Collection` оборачивает
  поля в `Required` группы `Default`.
- **`unevaluatedItems` у списка** — по своей схеме и её подсхемам (`allOf`, `$ref`), не по соседям в `allOf`: при
  `items` там не действует — отметка молча, `true`/`{}` — ничего; рядом с `contains`, `if`, `oneOf`/`anyOf` —
  предупреждение; `false` — `Count(max: n)`, `n` — наибольшая длина `prefixItems` там; схема без `prefixItems` — как
  `items` (`All`); схема рядом с `prefixItems` — предупреждение.
- `Collection` — композит (группы вложенных в `All`).

## 3. Вне рамок

- `unevaluatedProperties`: незаявленные свойства DTO теряет при десериализации, валидатору их не увидеть; остаётся
  предупреждение ядра.
- `prefixItems` рядом со схемой `items` (тип ядра), подсхемы с `$ref`/объектами.
- Различие `null` и отсутствующего ключа (как в G1/G2).

## 4. Тестирование

- Рантайм: настоящий валидатор 5.4–8, аннотации, группы, повторный вход, Infection 100 %.
- Мост: эмиссия, предупреждения, отметки ядра, группы, PHP 8.0 без `new`, аннотации для 7.4; `RealSymfonyTest` с `not`,
  `dependentSchemas`, `prefixItems`; матрица 5.4/6.4/7.4/8; Infection 100 %.

## 5. Ревью (2026-10-13 UTC)

Исправлено: группы полей `Collection` — `Optional([...], groups)` (CR-001: иначе исключающие группы роняли метаданные,
а обычные молча пропускали префикс); область `unevaluatedItems` — своя схема и подсхемы (MJ-001); `not: false` не
требует рантайма, `unevaluatedItems: true`/`{}` молчит, `then`/`else` без `if` не оценивают элементы (MN-001);
`required` в схеме `dependentSchemas` не решает (MN-002); предупреждение про `new` у `dependentSchemas` называет его,
а не `if`; документация (MN-003, SG-001); тесты групп, PHP 8.0, аннотаций и `dependentSchemas: false` (MN-004);
безымянный `not` схемы родителя (объявляет только чужие свойства) остаётся родителю (MN-005); предупреждения
`unevaluatedItems` — в его месте (SG-002).

Повторное ревью (2026-10-13 UTC): `unevaluatedItems` подсхемы, кроме `false`, оценивает все элементы — внешний молчит
(MJ-002); без эффекта у не-списков (`prefixItems: []`, `unevaluatedItems: true`/`{}`) — без предупреждения; union
считается оценивающим, только если он не сводится к одному члену (nullable `oneOf`/`anyOf`); безымянный `not`
относится к родителю по месту (вне собственной схемы класса), а не по именам свойств; кортежи — отдельный
`TupleConstraints`; группы — в конструктор `ClaimedConstraints`; `@phpstan-type NamedBranch`.

## 6. Унаследованные свойства (пункт 4 владельца)

Ядро 1.5 даёт `ClassContext::ancestors()` (предки, ближайший первым, со своими свойствами и `source()`). Мост
(`ClassProperties`): имена `dependentRequired`, условий, `not` и `dependentSchemas` ищутся среди своих и унаследованных
свойств (ближайший предок важнее). Место принадлежит предку, если до него доходит `Keywords` ближайшего предка от его
собственной схемы (то, что он сам проверяет): такие места оставляются ему молча и не отмечаются потомком (предок со
`x-validator-skip` не отметит — ядро предупредит), пары `dependentRequired`, которые он перечисляет, не повторяются
(Symfony наследует его constraint'ы). Родитель вне прогона: его свойства неизвестны — предупреждение «not a property».
`patternProperties` по унаследованным свойствам — без изменений (G2, свой обход `targets()`).

Финальное ревью (2026-10-13 UTC): атрибуция по префиксу `source()` заменена на места `Keywords` предка (BR-1: примесь
предка проверялась дважды; BR-2: inline-подкласс внутри схемы предка терял свои проверки); BR-3 — отметка только своих
мест; BR-5 — `RealSymfonyTest::testChecksInheritedPropertiesOnce`; BR-6 — `unevaluatedItems` рядом с не-списком
`prefixItems` не проверяется. Оставлено: одинаковые `not`/`if` в схеме потомка и предка дают два нарушения (BR-8; пары
`dependentRequired` сравниваются, условия — нет: сравнение готовых constraint'ов ради повтора, написанного дважды, не
окупается; описано в README); общий примитив «места предка» с `patternProperties` (BR-9) — при следующей правке G2;
порядок `Collection` перед `Count`/`All` (BR-10) — без значения для нарушений.
